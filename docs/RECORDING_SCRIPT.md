## 4:50–6:05 Question 4 Architecture guiding implementation

**Show telemetry.py, rules.py, service.py, storage.py, and config/rules.json.**

The architecture guided implementation by separating responsibilities.
Telemetry validation checks timestamps, numeric ranges, service availability,
and error counts. Only the fields needed by the prototype are retained.

The rule-processing module evaluates contextual conditions. Detection and
classification are combined in one function within that module. Contextual
condition checks are separated into their own function. The service module connects validation, classification, and storage.
SQLite persistence is handled in its own module, while the dashboard presents
results through the local application routes.

This structure helps me trace unexpected behavior. If data are valid but a
priority is wrong, I can inspect the rules without rewriting the dashboard.
The thresholds are stored in configuration rather than hidden in the interface.

Security considerations also influenced this version. Administrator login is
required to access stored records and report exports. The password is generated
at startup, and sessions expire. These are initial local safeguards, not a claim
that the application is ready for public production deployment.
